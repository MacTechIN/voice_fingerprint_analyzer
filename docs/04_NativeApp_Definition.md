# 네이티브앱 개발 정의서 (Windows, Android, Linux, iOS, MacOS)

## 1. 아키텍처 개요
단일 코드베이스(Flutter)로 5개 OS를 지원하되, 앱의 용량(APK/IPA 크기)을 최소화하고 UI/UX 반응성에 집중하는 구조. 무거운 머신러닝 라이브러리는 일절 포함하지 않음. VAD·음성 향상·분리·임베딩·스푸핑 탐지 등 모든 분석은 서버가 전담하며, 앱의 책임은 **분석 품질이 보장되는 오디오를 수집해 전달하는 것**까지로 한정한다.

## 2. 기술 스택
*   **Core Framework:** Flutter (Dart).
*   **Audio 패키지:** `record` (오디오 캡처), `audio_waveforms` (녹음 중 시각적 피드백).
*   **Network 패키지:** `dio` (Multipart API 통신 및 타임아웃 처리).

## 3. OS별 네이티브 요구사항 제어
*   **공통:** 마이크 접근 권한 요청 로직 (`permission_handler`).
*   **네트워크 권한:** 모든 OS에서 외부 인터넷 접속 권한 필수 (`INTERNET` permission in Android, Mac/iOS 샌드박스 네트워크 허용).

## 4. 녹음 품질 가이드 (서버 파이프라인 연계 요구사항)
서버 임베딩 모델은 짧거나 오염된 발화에서 신뢰도가 급락하므로, 클라이언트는 UI 수준에서 다음을 강제·유도한다.
*   **오디오 규격:** 16kHz, 16-bit, Mono WAV로 캡처 (서버 규격과 일치 — 서버 측 리샘플링 왜곡 방지).
*   **최소 발화 길이:** 녹음 3초 미만 시 전송 차단 및 재녹음 안내 (VAD 통과 후 유효 발화가 줄어드는 점을 감안한 여유분). 등록(Enrollment) 시에는 5초 이상 권장 문구 표시.
*   **발화 유도 스크립트:** 등록·검증 화면에 읽기 안내 문구를 제시하여 충분한 음소 다양성 확보.
*   **환경 안내:** 녹음 전 "조용한 곳에서, 기기를 입 가까이" 안내. 입력 레벨 미터로 과소·과대 입력(클리핑) 실시간 경고.
*   **서버 반려 처리:** 서버가 `speech_duration` 부족·품질 미달로 반려한 경우(4xx + 사유 코드), 사유별 맞춤 재녹음 안내 UI 표시.

## 5. 앱 내 데이터 플로우 (UI/UX)
1.  **초기 등록 (Enrollment):** 안내 문구 출력 -> 녹음 버튼 클릭 -> 오디오 파일 로컬 임시 저장 -> `POST /api/v1/enroll` 호출 -> "등록 완료" 수신.
2.  **본인 인증 (Verification):** 마이크 버튼 누른 상태로 발화 -> 로컬 임시 저장 -> `POST /api/v1/verify` 호출 -> 서버 대기열 로딩 UI(스피너) -> JSON 응답 수신 후 화면에 `동일인 일치율 95.4%` 렌더링 -> 임시 파일 삭제.
3.  **스푸핑 차단 응답 (Phase D):** 서버가 합성 음성 의심(`spoof_score` 임계 초과)으로 차단한 경우, 일치율 대신 "실제 음성 확인 실패" 안내와 재시도 플로우 표시 (탐지 상세 사유는 보안상 비노출).

## 6. 개인정보 및 데이터 처리 원칙
*   오디오는 전송 성공 즉시 로컬 임시 파일 삭제 (FR-02와 일치).
*   서버 역시 분석 후 원본 오디오를 파기하고 벡터만 저장함을 온보딩 화면에 고지 (생체정보 처리 동의 UX 포함).
